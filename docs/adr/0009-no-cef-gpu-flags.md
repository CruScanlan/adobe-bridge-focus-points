# Pass no GPU flags to CEF

Supersedes [ADR-0006](0006-cef-gpu-flags-for-vm-display.md). The manifest's `CEFCommandLine` carries `--enable-nodejs` and nothing else, so the panel is GPU-composited like Adobe's own. Bridge docks a CEP panel inside a tab-panel window created without `WS_CLIPCHILDREN` and repaints straight over it; a GPU-composited panel is unaffected because its frames are a separate surface above that window, but a software-rendered one is wiped while the page keeps running. `--disable-gpu`, `--disable-gpu-compositing` and `--disable-direct-composition` each force software rendering, so the flags added to cure a blank panel were what kept causing it: on 2026-11-11 the same three flags gave blank and drawn launches minutes apart, and removing them gave six drawn launches in a row on Bridge 16.0.8. Do not add any of them back. If a machine can only render in software the panel may be blank there; the remedy is the unshipped helper in `tools/clipfix.cs`, not the flags. A blank panel is not fixed until the suspected cause has been switched off and on again — one good restart proved nothing twice.
